# MediRescue AI: API Contract (Member 2 backend)

Share this file with Members 1, 3 and 4. Live, clickable docs are at `http://<backend-url>/docs`.

- Base URL (local): `http://127.0.0.1:8000`
- Every request except login needs `Authorization: Bearer <access_token>`
- All timestamps are **UTC**. All patient data is **synthetic**.
- The common ID passed everywhere is `incident_id`, e.g. `INC-2026-0001`.

## Error format (every error)

```json
{ "detail": { "error": "RESCAN_REQUIRED", "message": "No face detected. Please capture again." } }
```

| HTTP | Meaning | Frontend should… |
|---|---|---|
| 401 | `NOT_AUTHENTICATED`, `INVALID_TOKEN`, `TOKEN_EXPIRED`, `TOKEN_REVOKED` | send user to login |
| 403 | `FORBIDDEN`: wrong role / other hospital / other incident | show "Access denied" |
| 404 | not found | show message |
| 409 | `INVALID_TRANSITION`, `ALREADY_DISPATCHED`, `AMBULANCE_UNAVAILABLE`… | refresh and show message |
| 422 | `RESCAN_REQUIRED` or invalid input | ask for re-capture / fix input |
| 503 | `MATCHING_UNAVAILABLE` | show retry button |
| network error | backend down | show offline/retry state |

## Status flow

```
SCAN_PENDING → SCAN_RECEIVED → IDENTITY_VERIFIED ─┐
                            └→ MATCH_REVIEW ───────┤ (review/confirm → IDENTITY_VERIFIED)
                                                   ▼
                     EMS_NOTIFIED → AMBULANCE_ASSIGNED → EN_ROUTE → ARRIVED → IN_ER
                     → UNDER_TREATMENT → STABLE | OTHER_OUTCOME → CLOSED
```

- Dispatch is allowed **before** identity is confirmed (care is never blocked by identity).
- Who can set what with `PATCH /status`: EMS → `EN_ROUTE`, `ARRIVED`. Hospital → `ARRIVED`, `IN_ER`, `UNDER_TREATMENT`, `STABLE`, `OTHER_OUTCOME`, `CLOSED`. Admin can force `CLOSED` with notes.
- `GET /api/meta` returns the statuses and allowed transitions as JSON.

## Auth

### `POST /api/auth/login`
```json
{ "username": "ems1", "password": "ems123" }
```
→
```json
{ "access_token": "eyJ...", "token_type": "bearer", "expires_in_minutes": 480,
  "user": { "staff_id": "STF-002", "username": "ems1", "role": "ems", "hospital_id": null } }
```

### `POST /api/incidents/{id}/access-token` (ems, hospital, admin)
Short-lived emergency token tied to **one incident + your role**. Body (optional): `{ "expires_minutes": 30 }`
→ `{ "access_token": "...", "jti": "...", "expires_at": "..." }`. It works only on that incident's
profile / tracking / status / notes / timeline routes.

### `DELETE /api/access-tokens/{jti}`: revoke it.

## Member 1: Emergency app

### 1. `POST /api/incidents` (field_responder)
```json
{ "client_request_id": "<uuid generated by app>", "latitude": 28.4744, "longitude": 77.49,
  "reported_at": "2026-11-25T17:42:10Z", "severity": "HIGH" }
```
- No GPS? Leave out `latitude`/`longitude`; you get `"location_available": false` and a `warning`.
- Re-sending the same `client_request_id` returns the same incident with `"duplicate": true` (HTTP 200).

→ 201
```json
{ "incident_id": "INC-2026-0001", "status": "SCAN_PENDING", "location_available": true, "duplicate": false, ... }
```

### 2. `POST /api/incidents/{id}/scan` (field_responder)
```json
{ "scan_data": [0.0123, -0.0456, ...128 numbers...], "face_detected": true, "quality_score": 0.9,
  "latitude": 28.4744, "longitude": 77.49, "timestamp": "2026-11-25T17:42:30Z" }
```
`scan_data` can be **either** a list of 128 numbers (embedding mode) **or** a base64 JPEG/PNG string
(image mode, needs DeepFace installed on the server).

→ 200
```json
{ "incident_id": "INC-2026-0001", "status": "IDENTITY_VERIFIED", "match_result": "VERIFIED",
  "identity_confirmed": true, "candidates_count": 1, "message": "Identity verified..." }
```
`match_result`: `VERIFIED` | `AMBIGUOUS` | `NEEDS_REVIEW` | `NO_MATCH`. No name or medical data is returned to the app.

→ 422 `RESCAN_REQUIRED` if no face / low quality / wrong embedding length: ask for another capture.

### Testing without a face model: `GET /api/demo/test-scan`
| Query | Gives |
|---|---|
| `?user_id=USR-001` | VERIFIED (Aarav Mehta) |
| `?user_id=USR-003` | AMBIGUOUS (Riya has a look-alike twin) |

| `?user_id=USR-006` | NO_MATCH (consent revoked) |
| no params | NO_MATCH (stranger) |

Copy the returned `scan_data` into the scan request.

## Member 3: EMS dashboard

| Method & path | Purpose |
|---|---|
| `GET /api/incidents?status=IDENTITY_VERIFIED,MATCH_REVIEW` | Incident queue (comma-separated statuses) |
| `GET /api/incidents/{id}/profile` | EMS-level emergency profile |
| `GET /api/incidents/{id}/candidates` | Possible matches when AMBIGUOUS / NEEDS_REVIEW |
| `POST /api/incidents/{id}/review` | `{ "decision": "CONFIRM", "user_id": "USR-003", "notes": "Checked ID card" }` or `REJECT` |
| `POST /api/incidents/{id}/dispatch` | `{ "ambulance_id": "AMB-001", "hospital_id": "HOSP-001" }`, both optional (auto-nearest) |
| `GET /api/incidents/{id}/tracking` | Incident + ambulance + hospital coordinates, distance, ETA |
| `POST /api/incidents/{id}/tracking/simulate` | Demo: moves ambulance one step closer |
| `PUT /api/ambulances/{id}/location` | `{ "latitude": .., "longitude": .. }` real/simulated GPS |
| `PATCH /api/incidents/{id}/status` | `{ "status": "EN_ROUTE" }` then `ARRIVED` |
| `GET /api/ambulances` | Fleet with status |
| `GET /api/incidents/{id}/notifications` | Family alert log (`SENT` / `FAILED`) |
| `POST /api/incidents/{id}/notifications/retry` | Retry failed alerts |

Dispatch response includes `family_notifications: { "sent": 2, "failed": 0, "skipped_reason": null }`.
Family alerts are sent automatically on dispatch (or later, as soon as identity is confirmed).
Demo: numbers starting `+000` always fail so you can show failure handling (USR-005 has one).

**EMS profile fields:** `name, age, gender, blood_group, allergies, conditions, medications, implants, emergency_contacts[name, relationship, phone]`

## Member 4: Hospital / ER dashboard

| Method & path | Purpose |
|---|---|
| `GET /api/hospitals/{hospital_id}/incoming` | Trauma queue for your hospital (no names) |
| `GET /api/incidents/{id}/profile` | Full hospital-level profile (audited) |
| `GET /api/incidents/{id}/tracking` | Ambulance ETA |
| `PATCH /api/incidents/{id}/status` | `ARRIVED` → `IN_ER` → `UNDER_TREATMENT` → `STABLE`/`OTHER_OUTCOME` → `CLOSED` |
| `POST /api/incidents/{id}/medical-notes` | `{ "note_type": "HANDOFF", "notes": "..." }` (HANDOFF / TREATMENT / NOTE) |
| `GET /api/incidents/{id}/medical-notes` | Notes |
| `GET /api/incidents/{id}/timeline` | Status + notes timeline |
| `GET /api/incidents/{id}/audit` | Audit history page |
| `GET /api/hospitals/{id}/blood-bank?incident_id=...` | Demo stock + compatible units + `READY`/`LOW`/`UNAVAILABLE` |
| `PATCH /api/hospitals/{id}/er-status` | `{ "er_status": "OPEN" \| "BUSY" \| "DIVERTING" }` |

Hospital staff only see incidents **assigned to their hospital**.
**Hospital profile fields:** EMS fields + `dob, donor_preference`, contacts with `priority`.
